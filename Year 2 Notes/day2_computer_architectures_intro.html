Computer Architectures

Von Neumann · Harvard · Non-Von Neumann

Motivation

Why Does Architecture Matter?

  • Architecture defines how a computer's main components are connected and communicate.
  • It determines performance, power consumption, cost, and programmability.
  • The same algorithm can behave very differently depending on the underlying architecture.
  • Every device you use — phone, laptop, microcontroller — reflects a deliberate architectural choice.
Analogy: Think of architecture as the blueprint of a building. You can furnish it differently, but the blueprint shapes what's possible.
Von Neumann Architecture

The Von Neumann Model (1945)

Proposed by John von Neumann. Became the dominant model for general-purpose computers.

Core idea: Store both data and instructions in the same memory, accessed over a single shared bus.

  • Memory is a single, flat address space.
  • CPU fetches and executes one instruction at a time: Fetch → Decode → Execute.
Von Neumann Architecture

Key Properties & The Bottleneck

Strengths

  • Simple, unified memory model
  • Easy to program — one address space
  • Hardware is straightforward to build
  • Dominant in general-purpose CPUs

The Von Neumann Bottleneck

  • Data and instructions share a single bus
  • CPU must wait for memory on every fetch
  • Memory bandwidth limits performance
  • Partially addressed by caches & pipelines
Key insight: The bottleneck is a fundamental constraint, not a bug — it's a direct result of the shared-bus design. This is why caches exist.

The Harvard Architecture

Developed at Harvard in the 1940s (Mark I). Uses physically separate memories and buses for instructions and data.

  • Two separate address spaces: one for code, one for data.
  • CPU can fetch an instruction and read/write data simultaneously.
  • Common in microcontrollers and DSPs (e.g., AVR, PIC, ARM Cortex-M).
Harvard Architecture

Strengths, Limits & Modified Harvard

Strengths

  • No bottleneck between code & data fetches
  • Higher throughput in signal processing
  • Instruction memory can be read-only (ROM) — enhancing reliability

Limitations

  • More complex hardware (two buses)
  • Cannot easily load code at runtime
  • Harder to program in some scenarios
Modified Harvard: Modern CPUs (e.g., ARM) use separate L1 caches for instructions and data, but a unified main memory — getting the speed benefit without full separation.
Non-Von Neumann Architectures

Breaking the Von Neumann Mold

Any architecture that departs fundamentally from the sequential, single-processor, shared-memory model is broadly called "Non-Von Neumann."

  • Dataflow architectures — instructions execute when their operands are ready, not in program order.
  • Systolic arrays — grids of simple processors that pass data rhythmically (used in ML accelerators).
  • Neuromorphic chips — inspired by biological neural networks (e.g., Intel Loihi).
  • Quantum computing — exploits superposition and entanglement instead of binary bits.
Why explore alternatives? Von Neumann's bottleneck and the end of easy clock-speed scaling have pushed researchers toward radically different models.
Non-Von Neumann Architectures

Real-World Examples

GPU (Graphics Processing Unit)

  • Thousands of small cores executing in parallel
  • Thrives on data-parallel workloads (graphics, AI training)
  • NVIDIA CUDA, AMD ROCm

TPU (Tensor Processing Unit)

  • Google's systolic-array accelerator
  • Optimised for matrix multiply (neural networks)
  • Orders of magnitude more efficient than CPUs for ML

Neuromorphic Chips

  • Spiking neural network model
  • Extremely low power at the edge
  • Intel Loihi 2, IBM TrueNorth

Quantum Processors

  • Qubits vs. classical bits
  • Potential for certain problems (cryptography, simulation)
  • IBM Quantum, Google Sycamore

Hybrid & Modern Systems

Where Does Your Device Fit?

Real-world systems rarely fit neatly into one category. Modern chips are hybrids:

  • Your laptop/phone CPU — logically Von Neumann, but with split L1 caches (Modified Harvard internally).
  • Embedded microcontrollers (Arduino, STM32) — true Harvard: code in Flash, data in SRAM.
  • GPU inside your laptop — massively parallel non-Von Neumann co-processor.
  • Apple M-series SoC — CPU cores + GPU cores + Neural Engine, all on one chip.
Architecture isn't binary — it's a spectrum of design choices. The goal is always the same: the best trade-off of performance, power, and cost for the target workload.
Summary

Key Takeaways

  • Von Neumann — unified memory, single bus, simple and universal, but bottlenecked.
  • Harvard — split memories allow simultaneous instruction and data access; common in embedded systems.
  • Modified Harvard — the practical compromise used in virtually every modern processor.
  • Non-Von Neumann — a family of alternatives (parallel, dataflow, neuromorphic, quantum) that sidestep the bottleneck for specialized workloads.
  • All real-world systems are hybrids — knowing the underlying model helps you understand performance and trade-offs.
